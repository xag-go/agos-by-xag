# Glossary

The words AGOS uses, in alphabetical order.

| Word                      | Meaning                                                                                                                                                                                                      |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **agos_action**           | The Co-Founder's tool for changing AGOS. Each call does one **operation** and shows a card with Undo or Approve.                                                                                             |
| **agos_guard**            | AGOS's Hermes plugin. It runs inside each Hermes gateway and adds approvals, AGOS's tools, Telegram cards and rooms. It talks to the core over HTTP.                                                         |
| **Approval**              | A risky action an agent wants to take (delete, send, pay, install) that waits for the owner's Allow or Deny.                                                                                                 |
| **Artifact**              | A file or document the team made on a card.                                                                                                                                                                  |
| **Automation**            | Work that starts by itself: on a schedule (a Hermes cron job), when another app sends a webhook, or both.                                                                                                    |
| **Backup (.agosb)**       | One encrypted file with AGOS's database, the workspace files and Hermes's own backup of every root. Holds no keys (they are re-entered after a restore). Needs the backup password to open.                  |
| **Brain**                 | Ways of working the whole team learned, shared by every workspace. It never holds project data.                                                                                                              |
| **Bridge**                | The core's routes the `agos_guard` plugin calls (`/hermes-bridge/<workspace>/…`), checked with a per-workspace key.                                                                                          |
| **Card**                  | One task on the **Kanban**. It has a title, a description, an assignee, comments, a chat and documents.                                                                                                      |
| **Channel**               | A place outside the web app where a chat also lives, such as a Telegram bot, group or topic.                                                                                                                 |
| **Co-Founder**            | A workspace's lead agent. It plans with the owner, hires members, hands out work and can do anything the owner can do in the app. In Hermes it is the root's default profile.                                |
| **Connector**             | An outside app or MCP server a workspace may use (Google, GitHub, Composio apps…). Turned on per workspace, each with its own sign-in.                                                                       |
| **Contract (Hermes)**     | The list of Hermes internals AGOS depends on (`engine/hermes_contract.py`). Checked before every Hermes upgrade.                                                                                             |
| **Core**                  | `agos-core`, the Python service that holds AGOS's data and rules and controls Hermes. Port 8766 on 127.0.0.1.                                                                                                |
| **Egress proxy**          | `agos-egress`, the only way out of a sandbox. It lets traffic reach the public internet only.                                                                                                                |
| **Gateway**               | The Hermes process that serves one **root**: its agents, chats, cron, Kanban dispatcher and Telegram. One per workspace.                                                                                     |
| **Hermes Agent**          | The open-source agent engine by Nous Research that runs everything in AGOS.                                                                                                                                  |
| **Hermes Gateway (AGOS)** | In the target design, the one AGOS package allowed to talk to Hermes (`hermes_gateway/`). Not the same as a Hermes **gateway** process.                                                                      |
| **Inbox**                 | The list of everything that waits for the owner's decision in a workspace.                                                                                                                                   |
| **Kanban**                | A workspace's task board. It is Hermes's own Kanban; AGOS adds views, labels, holds and reviews.                                                                                                             |
| **Kit**                   | What a new member needs to work well: skills, docs and examples, connectors, key names and its model. The owner edits it before approving a hire; AGOS shows a Readiness checklist, then an onboarding test. |
| **Managed scope**         | Hermes's folder of settings that apply to every root at once (`hermes-managed/`). AGOS writes shared settings there.                                                                                         |
| **MCP server**            | A tool server in the Model Context Protocol. Defined once in Settings → Connectors, turned on per workspace.                                                                                                 |
| **Member (agent)**        | An agent on a workspace's team, with a role, a model and a kit. In Hermes it is a profile under the workspace's root. Members are always agents.                                                             |
| **Migration**             | A change to AGOS's database schema. Append-only: a shipped one never changes.                                                                                                                                |
| **Operation**             | One thing that can be done in AGOS (create a card, hire a member…), with validate, do, undo, audit and gate. See ARCHITECTURE §10.                                                                           |
| **Owner**                 | The one person an AGOS installation serves. AGOS has no other users and no login.                                                                                                                            |
| **Ownership registry**    | `db/ownership/`: every table, column and setting AGOS stores, each with the reason Hermes can't hold it.                                                                                                     |
| **Profile**               | A Hermes agent identity inside a root: its config, `SOUL.md`, memory and skills.                                                                                                                             |
| **Ratchet**               | A gate test that counts today's rule violations and only lets the number go down.                                                                                                                            |
| **Rehearsal**             | Test a restore: AGOS opens a backup in a temporary place and checks it, without touching the live data.                                                                                                      |
| **Room**                  | A group chat. It is a Hermes room: the Co-Founder directs which members answer.                                                                                                                              |
| **Root**                  | One Hermes home per workspace (`<data>/hermes/agos-<id>`), with its own config, memory, sessions, skills, cron and Kanban.                                                                                   |
| **Sandbox**               | The Docker container per workspace where every agent tool runs. It sees only the workspace's folders and holds no secret.                                                                                    |
| **Service (target)**      | In the target design, the one module that owns an action set (Board, Team, Automations…). Every caller goes through it.                                                                                      |
| **Session**               | A chat with the Co-Founder or one member. It is a Hermes session.                                                                                                                                            |
| **Skill**                 | A reusable method an agent can load (`SKILL.md`). Skills hold method only, never a project's data.                                                                                                           |
| **SOUL.md**               | A profile's identity text in Hermes. AGOS writes the workspace identity and its fixed working rules there.                                                                                                   |
| **System Log**            | Warnings and errors from the core, shown in each workspace's **Log** tab.                                                                                                                                    |
| **Wall**                  | The Linux Landlock rules around each Hermes gateway: it can only reach its own root and its workspace's folders.                                                                                             |
| **Webhook relay**         | `agos-hooks`, port 8767. The only AGOS port a public tunnel may point at. It passes only signed webhook posts to the right workspace.                                                                        |
| **Workspace**             | One project. It has its own Hermes root, Co-Founder, team, files, chats, keys and Kanban, closed to every other workspace.                                                                                   |
