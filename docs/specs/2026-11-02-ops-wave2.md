# Ops wave 2: staging, rollback, flags, backup watch, SQLite checks, disk/RAM, diagnostics

Status: built on `eng/ops` for the owner's review (wave 2, lane OPS). Source: the
docs/ops audit (its docs-ops part, §3-§7, steps C6, D1, D2, D4-D6, F1-F3, G1).

## 1. Staging (`agos staging up|down|status|refresh`)

A second AGOS on the same machine, for trying a release on a copy of the real data.

- Name `staging`; units `agos-staging-core|web|hooks`; ports core 8866, web 3100,
  hooks 8867, first webhook port 9100; everything under `<agos home>/agos-staging/`
  (`app/` a git worktree of the live checkout, `data/`, `backups/`); config
  `/etc/agos/staging.conf`. Same Unix user as live (the Hermes gateways are that user's
  services), but its own Hermes profile prefix `stg-`, so its roots, Docker networks
  (`agos-net-stg-…`) and egress proxy (`agos-stg-egress`, from `AGOS_EGRESS_NAME`) never
  touch live's. Its gateways are the user services whose home is under the staging data.
- `refresh` (and the first `up`): newest live backup → `restore_and_verify.py` into a
  temp folder → staging data. Each root zip is imported by Hermes's own `hermes import`
  into `<staging roots>/stg-<ws>` (the live name with the prefix swapped). The shared
  home's backup is NOT imported (that is live's `~/.hermes`).
- Quiet: `AGOS_STAGING=1` in the staging core: the AGOS channel and automation loops do
  not start, phone push and Telegram sends are dropped, and at start every Hermes cron
  job of every staging root is paused through Hermes's own `hermes cron pause`. A
  backup holds no key (ADR 0023), so the staging roots have no bot tokens: no
  Telegram polling. A banner line in `agos staging status` says so.
- `down` stops and disables the staging units and gateways; data stays. `down --purge`
  removes the staging folder and units.
- Promote = `agos update` on live to the same commit (staging never writes live).

## 2. Rollback

- Every update snapshot (`agos-backups/update-<stamp>/`) holds `agos.sha`,
  `hermes.pin`, `agos.db` and now `roots.tar`: each root's and member's
  `config.yaml`, `profile.yaml`, `SOUL.md`, `.env`, `plugins/`, `cron/jobs.json` and
  the managed scope `config.yaml` (no sessions, no memory: those are not rewritten by
  a release). `.env` holds keys: the tar is 0600 in a 0700 folder and never leaves the
  machine; it is deleted with the snapshot (last 3 kept).
- The update's own auto-rollback restores roots.tar too.
- `agos rollback [--to <stamp>] [--yes]`: back to the snapshot's code, Hermes pin,
  database and roots files; the current database is kept aside first
  (`update-<stamp>/rolled-from.db`).
- After a successful update, a watch (`agos update-watch`, a transient systemd timer
  for `AGOS_WATCH_MINUTES`, default 10) checks every minute: core `/health?deep=1`
  ok, web `/` 200, and every gateway that ran before the update is active. Three
  failed checks in a row = automatic `agos rollback` to that update's snapshot, and
  the update card says `rolled_back`.

## 3. Feature flags

`actions/flags.py`: a typed registry `FLAGS = {name: Flag(default, title, about)}`,
values in `app_settings["flags"]`, env override `AGOS_FLAG_<NAME>=0|1` (staging can
force one), unknown names refused. `GET /flags`, `PUT /flags/{name}`. Web: Settings →
General → **Labs** card (same `Card` as its neighbours, one switch per flag). Kill
switch = turn it off. Co-Founder parity: `set_flag` (Undo puts the old value back).
The first flag is `labs_demo` (no behaviour; proves the path) until a real one lands.

## 4. Backups watch

In a new `actions/ops_watch.py` loop (every 15 min):

- no backup password, or the last good backup older than 48 h (schedule not off) →
  an ERROR on `agos.backup` (so Settings → Errors + the `agos.error` notification,
  once per issue) and a `warnings` line on `GET /backups` that Settings → Server &
  backup shows as a banner (the `LimitWarnings` look);
- monthly: the restore rehearsal of the newest backup (`backups.rehearse`, into a temp
  folder, file and table counts), plus `PRAGMA integrity_check` of the restored db;
  logged, failure = ERROR;
- old side folders: `agos-data.before-restore-*` beyond the newest one, and
  `restore-*` temp folders older than a day, are removed.
  Backups stay on this machine (owner's choice): no off-machine copy is added.

## 5. SQLite

The connection already sets `foreign_keys = ON`; a test pins it. Weekly
`PRAGMA integrity_check` + `PRAGMA foreign_key_check` on agos.db; not ok = ERROR.

## 6. Disk and RAM

Every minute: free disk on the data folder < 10%, or `MemAvailable` < 10% of
`MemTotal`, for 5 minutes in a row → one ERROR (`agos.ops`), again only after it
recovered. journald's cap is the ISO's job (not here).

## 7. Diagnostics

`GET /diagnostics` → a redacted text report: versions (AGOS, Hermes), OS, health
(deep), disk/RAM, last 20 open error issues (type, count, where — no message
text beyond the redacted one-liner), backup status (no folder names beyond the
default), flags, update state. No chat, card, file or workspace names; secrets
wiped by `system_log.redact`. `agos doctor --bundle` writes it to a file; Settings →
Errors gets a **Copy diagnostics** button.

## Hard rules touched

Hermes stays the engine (cron pause and root import are Hermes's own commands);
isolation (staging uses its own prefix, egress and data); Co-Founder parity
(`set_flag`); the owner's design (new Labs card and banner only, same components).
